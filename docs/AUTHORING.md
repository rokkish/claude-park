# ステージの作り方

既存ギミックの組み合わせだけなら、**コードは1行も書きません**（JSON 1つ + 登録2行）。
設計の背景は [SPEC.md](SPEC.md) §7、ツール化の予定は [TODO.md](TODO.md) を参照してください。

## 0. 座標系

- タイルは **24px**、画面は **40 × 18 タイル（960 × 432px）**。スクロールはありません。
- 座標は全て**タイル座標**。y は下ほど大きく、**行 r の上面 = `r * 24` px**。
- プレイヤーの当たり判定は **20 × 24px**（高さちょうど1タイル）。
- 床が行16なら、その上に立つもの（板・鍵・ゴール・スポーン）は**行15**を指定します。

## 1. グリッドを描く

`src/stages/stage-NN.json` をコピーして、`grid` の ASCII を書き換えます。

| 文字 | 意味 |
| --- | --- |
| `.` | 空 |
| `#` | 壁・床 |
| `-` `^` | 予約（一方通行床・トゲ）。**まだ動きません** |

行の長さが揃っていない、未知の文字がある場合は**ロード時に throw** します。静かに壊れません。

## 2. ギミックを置く

`gimmicks` 配列に、`type` とタイル座標を書きます。`emit` と `listen` に**同じ文字列**を使えば
つながります（発信側と受信側は互いを知りません）。

| type | 必須 | 任意 | 備考 |
| --- | --- | --- | --- |
| `plate` | `emit` | `w` `h` | 乗っている間だけ ON。**人でも箱でもよい** |
| `gate` | `listen` | `w` `h` `mode` `latch` | 閉じている間だけ Solid |
| `platform` | `to: {x,y}` | `w` `h` `speed`(既定80) `listen` `mode` | `listen` 無しなら**常時往復** |
| `key` | `id` | — | **人しか拾えない**（箱では拾えない） |
| `goal` | — | `w` `h` `requires` `needAllPlayers` | `requires` は鍵の `id` |
| `crate` | — | `w` `h` | 押せる箱。水平にしか動かない |

`mode` は `all`（既定・全部 ON）/ `any`（どれか ON）/ `none`（全部 OFF ＝反転）。
`latch: true` は一度 ON になったら戻りません。

**逆位相**（1つの信号で2つの足場を逆向きに動かす）に専用オプションはありません。
`x,y` と `to` を**入れ替えた足場をもう1つ置くだけ**です。

未登録の `type` はロード時に throw します。

## 3. 登録する

```ts
// src/stages/index.ts —— import を1行、配列に1行
import stage12 from "./stage-12.json";
export const STAGES: StageData[] = [ ..., stage12 as StageData, ... ];
```

配列の**並び順と `world` フィールドだけ**が表示ラベル（`2-4` など）を決めます。
id の番号は無関係なので、空いている番号を使って構いません。

新しいワールドを作る場合は `src/stages/worlds.ts` の `WORLD_NAMES` に1行足します
（足さないと選択画面に `?` が出ます）。

## 4. 遊んで確かめる

```bash
npm run dev          # http://localhost:5173/?stage=stage-12
```

`?stage=` にはラベル（`2-4`）でも id（`stage-12`）でも渡せます。選択画面を飛ばして直接始まります。

ブラウザを開かずに絵だけ見たい場合:

```bash
npx vite-node scripts/preview-stage.ts out.png <配列での順番> start
```

## 5. 検算する

**この数値がステージ成立の根拠です。** `src/game/tuning.ts` の `JUMP_VELOCITY` / `GRAVITY` から
決まっているので、そちらを変えたらここも再計算が要ります。

| 手段 | 到達高 | 水平到達 |
| --- | --- | --- |
| 単独ジャンプ | 62.5px（2.6タイル） | 約87px |
| 相方の頭に乗ってから | 86.5px（3.6タイル） | — |
| 箱＋頭に乗って | 110.5px | — |
| **二段ジャンプ**（頭に乗り、下の頂点で上が跳ぶ） | **149px** | 約102px |

### 落とし穴

- **高さで縛れるのは「そこに2人並べない」ときだけ。** 並べる場所なら 149px を超えさせるか、
  水平距離（102px 超）で縛ってください。3-2 と 3-3 はこれで2度作り直しています。
  2-4 は「足場が留まるのは板を踏んでいる間だけ＝1人しか居られない」を根拠に、
  中段より上を 72px で縛っています。
- **横方向の当たりは「押し合い」です。** 板を人の通り道に置くと、通る人が押さえ役を
  板から押し出します（1-4 で踏みました）。
- **箱は壁際に押し込むと戻せません。** 板は壁に密着させて置き、押し過ぎの事故を
  構造的に起こらなくします（3-2）。
- **`latch` が要るのは**「同時押しで開けたあと、誰かが板を離れないと先へ進めない」形のときです。
  無いと抜けている途中で閉じて挟まります（1-2）。
- **落ちても自力で戻れるか**を必ず確認します。戻れない穴は詰みです（`R` でやり直せますが、
  意図しない詰みは避けます）。

## 6. テストを書く

`tests/stageNN.test.ts` を作ります。**「想定手順を通しで踏んで `cleared` に至るテスト」は必須**です。
2-2 で「部品ごとのテストは全部通るのに、盤面としては詰んでいる」を一度出荷しています。

```ts
it("想定手順で2人ともゴールに到達できる", () => {
  // ...テレポートで配置し、実際にシミュレーションを回す
  expect(game.phase).toBe("cleared");
});
```

加えて `tests/progression.test.ts` の `CLEAR_SETUP` に1行足してください
（**未定義だとテストが落ちます**。ゴールと鍵のタイル座標を書くだけです）。

```ts
"stage-12": { goal: { x: 30, y: 3 }, key: { x: 12, y: 6 }, key2: { x: 10, y: 3 } },
```

最後に `npm test` と `npm run build`（型検査込み）を通します。
